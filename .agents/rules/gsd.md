# GSD project rule

Follow `PROJECT_RULES.md` as the canonical workflow and `GSD-STYLE.md` for its conventions.
Use `v2.md` as the project requirements source when initializing this project.
Keep `.gsd/SPEC.md`, `.gsd/ROADMAP.md`, and `.gsd/STATE.md` aligned with the active milestone.
Before implementation, make sure `.gsd/SPEC.md` is marked `FINALIZED`; then plan, execute, verify, and commit in that order.
Do not treat illustrative benchmark values or external references in `v2.md` as verified facts until their primary sources or actual datasets are checked.
